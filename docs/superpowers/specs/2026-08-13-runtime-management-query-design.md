# 运行管理页面查询设计

## 目标

为运行管理页面的 Compose 项目列表和独立容器列表增加查询功能，帮助用户在项目或容器较多时快速定位目标资源。

## 范围

- Compose 项目区域独立使用一个查询条件。
- 独立容器区域独立使用一个查询条件。
- 不增加状态筛选。
- 查询通过 URL 参数保留，刷新页面或分享链接后仍能得到相同结果。
- 查询在服务端执行，不新增 API，也不引入前端框架。

## 匹配规则

Compose 区域的查询关键词不区分大小写，匹配以下字段：

- 项目名
- 项目内容器名
- 项目内 Compose 服务名

独立容器区域的查询关键词不区分大小写，匹配以下字段：

- 容器名
- 容器 ID，包括完整 ID 和短 ID
- 镜像名

空白查询等同于未查询，显示该区域的全部资源。未匹配时保留表头并显示该区域的空结果提示。

## 交互设计

运行管理页面的两个区域各自提供一个搜索输入框和提交按钮：

- Compose 使用 `compose_q` 参数。
- 独立容器使用 `container_q` 参数。

提交任一查询时，另一个区域的查询参数也保留在 URL 中，因此两个区域可以组合查询，也可以只查询其中一个区域。输入框回显当前参数值。

区域标题显示过滤后的数量，结果表格仅渲染匹配项。页面状态完全由 GET 请求描述，不依赖 JavaScript。

## 架构

在 `web.py` 的 `/runtime` 路由读取 `compose_q` 和 `container_q`，调用 `runtime_inventory.py` 中的纯函数过滤已加载的 `RuntimeOverview`。过滤函数返回新的不可变 `RuntimeOverview`，不修改 Docker 读取结果，也不影响详情页和生命周期操作。

过滤逻辑按区域分开：Compose 项目保留匹配项目以及项目内匹配的容器；项目名匹配时保留该项目的全部容器，容器字段匹配时只保留匹配容器。独立容器只保留自身字段匹配的项。

模板负责渲染查询表单、回显输入值、保留另一查询参数和展示空结果提示。查询参数通过 `urllib.parse.urlencode` 生成，避免手工拼接导致特殊字符破坏链接。

## 错误处理

查询不会改变 Docker 读取和 Compose 读取的异常处理：Docker 不可用仍返回现有 503 页面，Compose 查询失败仍显示现有 Compose 错误提示。查询本身没有需要返回 4xx 的非法输入；任意文本均按普通关键词处理。

## 测试

- 单元测试覆盖大小写不敏感匹配、项目名命中保留全部项目容器、容器名/服务名命中只保留匹配容器、独立容器的名称/ID/镜像匹配，以及空查询不改变结果。
- Web 测试覆盖两个查询参数的独立过滤、参数回显、组合参数保留和未匹配空结果提示。
- 完成后运行运行管理相关测试和完整 server 测试。
