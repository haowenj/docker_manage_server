# 部署任务目录大小与手动删除设计

## 背景与目标

每次上传离线部署包时，服务端会在 `packages/<任务 ID>/` 保存原始 `archive.tar.gz` 和解压后的完整内容。同一份镜像归档通常同时存在于原始压缩包与 `extracted/images.tar`，因此历史任务目录会持续占用磁盘。

是否保留历史配置和部署包应由用户决定。本次不增加自动清理规则，而是在部署任务列表实时展示每个任务目录的大小，并为非活动任务提供显式删除操作。用户确认删除后，系统只删除该任务记录与任务包目录，不影响已经部署的应用及 Docker 资源。

## 范围

### 包含

- 部署任务列表新增“任务目录大小”列。
- 大小实时统计 `packages/<任务 ID>/` 当前所有普通文件的总字节数。
- 大小使用现有字节格式显示为 `B`、`KiB`、`MiB`、`GiB` 等。
- 非活动任务显示“删除”按钮，并在提交前弹框确认。
- 删除任务记录 `tasks/<任务 ID>.json` 和任务目录 `packages/<任务 ID>/`。
- Web 与 JSON API 使用同一项服务层删除能力和状态判定。
- 继续保留现有待审核任务详情页的“丢弃任务”入口及语义。

### 不包含

- 不自动、定时或按磁盘阈值删除任务。
- 不删除 `deployments/<app_name>/` 稳定部署目录。
- 不停止或删除容器、Compose 项目、网络、数据卷或 Docker 镜像。
- 不清理 Docker 构建缓存。
- 不缓存目录大小，也不把大小写入任务 JSON。
- 不增加批量删除、多选或一键清理功能。

## 任务目录大小

`TaskStore` 提供按任务 ID 计算任务目录大小的只读能力。它只从经过现有格式校验的 `packages/<任务 ID>/` 开始遍历，并遵循以下规则：

- 累加目录树中所有普通文件的 `st_size`；
- 不跟随目录符号链接；
- 符号链接自身不计入大小，也不读取其目标；
- 目录不存在时返回 `0`；
- 单个文件或子目录在统计过程中消失时跳过该项，使并发文件变化不会破坏整个任务列表；
- 权限错误或其他无法安全读取的文件系统错误不伪造精确结果，而是把该任务大小标记为不可用，页面显示“无法读取”，其他任务继续展示。

列表请求时为每个任务实时计算大小，不持久化结果。这样既有历史任务无需迁移即可显示当前真实占用，用户删除部分文件后刷新列表也会立即得到新值。

本功能展示的是任务包目录中文件的逻辑大小总和，用于辅助判断删除优先级；它不是文件系统块占用，也不包含稳定部署目录和 Docker 镜像存储，因此不承诺等于删除任务后磁盘 `df` 增加的字节数。

## 可删除状态

新增服务层 `delete_task(task_id)`，使用任务锁并在锁内重新读取任务状态。删除许可按状态分组：

- 禁止删除：`uploaded`、`extracting`、`deploying`。这些状态可能仍有后台上传、解压或部署操作正在访问任务目录。
- 允许删除：`pending_review`、`failed`、`deployed`。
- `discarded` 不会保留任务 JSON，因此正常情况下不会出现在列表中。

页面是否显示按钮只用于交互提示，不作为授权依据。服务端必须在提交时重新检查权威状态；列表渲染后任务若进入活动状态，删除请求返回冲突，不删除任何文件。

已部署任务可删除的是部署历史记录和上传工作区。其 `deployments/<app_name>/` 稳定目录、正在运行或已停止的容器、Docker 镜像、网络和命名卷均保持不变。

## 删除流程与存储边界

删除流程为：

1. 获取该任务的进程内任务锁。
2. 从 `tasks/<任务 ID>.json` 重新读取任务；不存在则报告未找到。
3. 验证当前状态允许删除。
4. 调用 `TaskStore.delete(task_id)`。
5. 返回被删除任务的基本信息供 API 响应使用。

`TaskStore.delete()` 保持现有安全边界：任务 ID 必须通过格式校验；任务包目录解析后的直接父目录必须是 `packages/`；删除范围只能是该任务目录和该任务 JSON。它不读取或删除 `DeploymentTask.deployment_dir`。

当前存储不是事务数据库。删除顺序继续为先删除任务目录、再删除任务 JSON。若任务目录删除成功而 JSON 删除失败，列表可能暂时保留一条大小为 `0 B` 的记录；用户可以再次删除。系统不得因为部分失败而返回成功，也不新增事务日志、回滚目录或软删除状态。

## Web 交互

部署任务表格列调整为：应用、归档、状态、任务目录大小、创建时间、更新时间、操作。

操作列保留“详情”，并为允许删除的任务增加红色“删除”按钮。按钮使用普通 POST 表单：

- `POST /deployments/<task_id>/delete`
- 使用现有 `data-confirm` 机制弹出确认框；
- 提示文案明确说明将永久删除任务记录、原始上传包和解压文件，但不会影响已部署服务、稳定部署目录或 Docker 数据；
- 成功后返回 `303` 到 `/deployments`；
- 任务不存在返回 404 错误页；
- 当前状态不允许删除返回 409 错误页；
- 文件系统删除失败返回错误页，不重定向为成功。

正在上传、解压或部署的任务不显示删除按钮。若目录大小无法读取，大小列显示“无法读取”，删除按钮仍按任务状态显示；用户可以用删除操作处理权限允许删除的目录，实际删除失败会得到明确错误。

现有详情页“丢弃任务”只在可编辑或可重试状态出现，继续调用 `discard()`。它仍用于用户放弃待审核或可恢复失败任务，不扩大到已部署任务。列表新增的“删除”统一调用 `delete_task()`。

## API

保留现有接口：

- `DELETE /api/deployment-tasks/<task_id>`

该接口从调用 `discard()` 改为调用 `delete_task()`，因此允许删除 `pending_review`、`failed` 和 `deployed`，拒绝 `uploaded`、`extracting` 和 `deploying`。成功继续返回被删除任务的 JSON 基本信息；任务不存在返回 404，活动状态返回 409，存储删除错误返回 500。

上传、审核、编辑配置、部署及任务查询 API 不改变。目录大小只用于服务端渲染的任务列表，本次不增加列表 JSON API 或在单任务 JSON 中加入动态大小字段。

## 异常与并发

- 目录大小统计与删除都从安全的 `TaskStore` 根目录和经过校验的任务 ID 计算路径，不接受客户端提供文件路径。
- 大小统计绝不跟随符号链接，避免读取任务目录外的数据。
- 删除在任务锁内完成，避免同一进程内与 `begin_deploy()`、`deploy()`、`edit_configuration()` 或另一次删除同时操作同一任务。
- 任务锁不能阻止其他进程直接修改数据目录；文件系统错误按实际失败返回，不伪装成成功。
- 删除已部署任务只影响历史任务数据，不需要应用锁，因为不访问稳定部署目录。
- 确认框是防误触交互，不替代服务端状态校验与路径校验。

## 测试策略

### 存储层

- 空任务目录和不存在的任务目录返回 0。
- 普通文件和嵌套普通文件正确累加。
- 文件符号链接和目录符号链接不计入、不跟随。
- 统计过程中目标消失时安全跳过。
- 权限或其他读取错误返回明确的不可用结果。
- 删除一个任务不影响其他任务和稳定部署目录。

### 服务层

- `pending_review`、`failed`、`deployed` 可以删除。
- `uploaded`、`extracting`、`deploying` 返回状态冲突且保留目录和 JSON。
- 已部署任务删除后任务目录与 JSON 消失，稳定部署目录及内容保留。
- 不存在任务报告未找到。
- 存储删除错误向上传递，不返回成功。
- `discard()` 的既有允许和禁止状态保持不变。

### Web 与 API

- 列表显示准确格式化的任务目录大小。
- 大小无法读取时单行显示“无法读取”，页面其余内容正常。
- 允许状态显示删除表单，活动状态不显示。
- 确认文案明确删除范围和不会影响的资源。
- Web 删除成功 303 返回列表，未找到返回 404，冲突返回 409，存储失败返回错误。
- API 可以删除已部署任务，同时保留稳定部署目录。
- API 对活动任务返回 409，对不存在任务返回 404。

## 交付验证

交付前运行存储、部署服务、API 与 Web 测试，再运行完整测试套件。额外执行 Python 语法检查、构建 wheel 并确认模板与代码被打包，以及 `docker compose config --quiet`。手工验证一个已部署任务：列表显示目录大小，确认删除后任务从列表消失，`packages/<任务 ID>` 与任务 JSON 消失，而 Compose 服务仍在运行、`deployments/<app_name>/` 仍完整存在。
