# 容器日志与终端独立页面设计

## 背景

容器详情页当前同时内嵌基本信息、日志查看器和 xterm 终端。终端视口只有最小高度，`ResizeObserver` 在父容器尺寸变化时调用 fit；xterm 调整行数后又可能撑高父容器，形成重复放大的尺寸反馈，最终让终端文本框和整个页面持续变长。

本次调整将日志与终端从容器详情页拆出，分别放入独立页面，并为两个内容区设置固定可视高度和内部滚动。

## 目标

- 在容器详情页顶部、容器名称右侧放置“查看日志”和“连接终端”按钮。
- 两个按钮分别在新浏览器标签页打开独立页面。
- 容器详情页不再渲染内嵌日志和终端，保持信息浏览页面简洁稳定。
- 日志和终端都使用固定可视高度，超出内容只在区域内部滚动，不拉长页面。
- 保留现有日志 API、终端 WebSocket、终端 resize 协议和明亮页面风格。

## 非目标

- 不修改容器生命周期操作。
- 不改变日志 API 或终端 WebSocket 的路径和协议。
- 不引入新的前端框架、构建工具或第三方在线资源。
- 不改变容器详情数据模型和 Docker Runtime 行为。

## 页面与路由

### 容器详情 `GET /containers/{container_id}`

页面继续显示容器状态、镜像、命令、端口、挂载、网络和标签。顶部标题区调整为：

- 左侧显示容器名称；
- 右侧依次显示状态、“查看日志”和“连接终端”；
- 两个操作链接使用 `target="_blank"`，并设置 `rel="noopener"`；
- 页面移除原有日志面板、终端面板、xterm 样式和终端模块脚本。

目标链接：

- `/containers/{container_id}/logs`
- `/containers/{container_id}/terminal`

### 日志页 `GET /containers/{container_id}/logs`

服务端渲染独立日志页面，顶部显示容器名称、状态和“返回容器详情”链接。页面复用现有日志查看器：

- 默认读取最近 100 行；
- 保留 tail 数量、时间戳和刷新操作；
- 日志通过现有 `/api/containers/{container_id}/logs` 获取；
- 日志内容继续按纯文本插入，避免把容器输出解释为 HTML。

日志输出区使用固定可视高度，内容超出后由自身纵向滚动；长行在输出区内横向滚动，不改变页面宽度。

### 终端页 `GET /containers/{container_id}/terminal`

服务端渲染独立终端页面，顶部显示容器名称、状态和“返回容器详情”链接。页面仅在此处加载本地 xterm 样式、xterm 脚本和终端模块。

终端继续连接 `/api/containers/{container_id}/terminal`，默认命令为 `/bin/sh`，并保留连接、断开及 resize 消息行为。

## 固定高度与滚动约束

日志输出区和终端视口都必须有明确的 `height`，不能只设置 `min-height`。高度根据视口大小限制在合理范围内，例如使用 `clamp()` 或带上下界的视口计算；窄屏使用单独的较小高度规则。

终端视口同时满足：

- `min-height: 0`，避免最小内容尺寸继续撑高父级；
- `overflow: hidden`，由 xterm 自身的滚动缓冲区处理终端历史内容；
- 父级网格或弹性元素允许收缩；
- `ResizeObserver` 只响应真实的视口宽高变化，不由终端子元素反向扩大父级。

日志输出区使用 `overflow: auto`，在固定区域内提供横向和纵向滚动。

## 视图与错误处理

三个容器页面使用一致的容器查询和错误映射：

- 容器不存在时返回同风格 HTTP 404 页面；
- Docker daemon 或 SDK 错误时返回同风格 HTTP 503 页面；
- 页面不暴露 Python traceback；
- API 和 WebSocket 的错误响应保持现状。

可提取共享的容器详情读取辅助函数，避免详情、日志和终端路由重复实现查询与异常处理，但不改变 Runtime 接口。

## 可访问性与安全

- 操作按钮使用可识别的链接文本，不只依赖图标。
- 新标签页链接增加可读的 `aria-label`，说明会打开新标签页。
- 新标签页链接设置 `rel="noopener"`。
- 容器名称、状态、日志和错误信息继续由模板自动转义或作为纯文本插入。
- 页面继续遵守现有 Content-Security-Policy，仅加载本站静态资源。

## 测试策略

### 路由与模板测试

- 容器详情页包含两个顶部链接，链接目标正确并带 `target="_blank"`、`rel="noopener"`。
- 容器详情页不再包含 `data-log-viewer`、`data-terminal-url` 或终端模块脚本。
- 日志页包含正确日志 API 地址、默认参数和返回详情链接。
- 终端页包含正确 WebSocket 数据属性、本地 xterm 资源和返回详情链接。
- 日志页和终端页覆盖未知容器 404 与 Docker 异常 503。

### 样式与行为回归

- 日志输出区和终端视口存在明确固定高度与内部滚动规则。
- 终端视口不再依赖单独的 `min-height` 撑开页面。
- 在浏览器中连接终端后持续观察页面，终端区域高度和页面 `scrollHeight` 保持稳定。
- 调整浏览器宽高后终端可以重新 fit，但不会持续触发自身增高。
- 写入超过一屏的终端输出后，通过 xterm 内部滚动查看历史内容。
- 写入长日志后，日志只在输出区内部滚动。
- 桌面和窄屏布局下，顶部标题、状态与操作按钮可以正常换行且不重叠。

### 全量回归

- 运行全部自动化测试，确保容器 API、终端 WebSocket、部署任务和页面安全行为不受影响。
- 构建镜像后验证三个容器页面及其本地静态资源可正常访问。

## 完成标准

- 容器详情页顶部名称右侧提供“查看日志”和“连接终端”按钮。
- 两个按钮在新标签页打开各自的独立页面。
- 日志和终端都具有固定可视高度，内容只在区域内部滚动。
- 连接终端、输出大量内容或调整窗口后，终端和页面高度不会无限增长。
- 自动化测试和浏览器回归验证通过。
