# Compose 容器详情弹框修复设计

## 背景与根因

Compose 项目详情页能够渲染“查看详情”按钮和对应的原生 `dialog`，但部署升级后点击按钮没有响应。本地当前 Chromium 中交互正常，说明后端数据、模板和样式结构有效。

故障由前端静态资源边界引起：页面始终引用固定地址 `/static/js/app.js`，升级后浏览器可能继续使用不含弹框逻辑的旧脚本；当前弹框查找逻辑还依赖 `CSS.escape()`，在未实现该 API 的浏览器或 WebView 中会在点击时抛出异常。

## 修复方案

采用两项互补的最小修改：

1. 为本地 CSS 和 JavaScript 静态资源 URL 增加由文件内容生成的版本查询参数。文件内容变化时 URL 随之变化，浏览器会加载新资源；内容不变时 URL 保持稳定，仍可正常缓存。
2. 为每个 Compose 容器详情弹框提供与按钮匹配的固定 DOM `id`。点击逻辑使用 `document.getElementById()` 查找弹框，移除对 `CSS.escape()` 的依赖。

现有原生 `dialog`、详情字段、关闭按钮、点击遮罩关闭以及无障碍标题关系保持不变。

## 组件与数据流

- 服务端模板辅助逻辑计算 `static/css/app.css` 和 `static/js/app.js` 的内容摘要，并把摘要作为 `v` 查询参数写入基础模板。
- Compose 详情模板把容器完整 ID 映射为按钮目标值和弹框 DOM `id`。
- `app.js` 读取按钮目标值，通过 `getElementById()` 获取弹框并调用 `showModal()`。

静态资源版本只影响浏览器缓存键，不改变 FastAPI 的静态文件路由，也不引入外部资源或构建步骤。

## 错误处理与兼容性

- 如果目标弹框不存在，点击保持无副作用，不抛异常。
- 如果浏览器不支持原生 `dialog.showModal()`，不在本次修复中引入完整 polyfill；当前问题的已知风险点是旧脚本缓存和 `CSS.escape()`。
- 资源摘要在服务启动/模块加载阶段从包内文件计算，不依赖 Git、镜像标签或外部服务。

## 测试与验收

- 模板测试确认 CSS/JS URL 包含内容版本参数。
- 单元测试确认资源内容变化会产生不同版本值。
- Compose 详情页测试确认按钮目标与弹框 `id` 一致。
- 前端资源测试确认弹框逻辑使用 `getElementById()` 且不再包含 `CSS.escape()`。
- 浏览器回归测试确认点击“查看详情”后弹框可见，关闭按钮和遮罩关闭仍有效。
- 完整 Python 测试、字节码编译和 Compose 配置校验继续通过。

## 范围外事项

- 不改造为自定义弹框组件。
- 不增加容器生命周期操作。
- 不修改 Compose 项目或容器数据模型。
