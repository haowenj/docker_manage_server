# 镜像列表批量删除设计

## 背景与目标

镜像管理列表目前只能进入详情页后删除单张镜像的可用名称，无法集中清理未被容器使用的完整镜像和构建过程产生的无 Tag 悬空镜像。

本次在镜像列表增加只作用于当前页的批量选择模式。用户选择镜像后先查看服务端实时预检结果；被任一现存容器引用的镜像整张保留，其余镜像在用户确认后按不可变镜像 ID 删除。执行前再次检查占用关系，避免预检之后新增容器导致误删。

## 范围

### 包含

- 镜像列表标题栏新增“批量删除”入口。
- 批量模式下为当前页每项显示复选框，并支持全选当前页、取消和已选数量展示。
- 仅提交当前页明确勾选的镜像，翻页、搜索或取消批量模式时清空选择。
- 预检弹框分别展示可删除镜像和被容器占用、不会删除的镜像。
- 被占用镜像展示所有引用容器，包括运行中和已停止的容器及其状态。
- 确认后删除所有仍未被容器引用的所选镜像，包括无 Tag 的悬空镜像。
- 删除使用不可变完整镜像 ID，语义是删除整张镜像及其 Tags，不复用详情页逐 Tag 删除语义。
- 执行结果区分已删除、被占用跳过、已不存在和删除失败。
- 删除后保持当前搜索条件和有效页码；当前页清空时回退到仍有效的上一页。

### 不包含

- 不跨分页保持或汇总选择。
- 不提供“选择全部搜索结果”。
- 不强制删除被容器使用的镜像，也不自动删除容器。
- 不改变现有详情页单张镜像名称删除功能。
- 不为批量删除新增无 JavaScript 降级表单。

## 页面交互

“本机镜像”标题栏新增“批量删除”按钮。点击后页面进入批量模式：表格最左侧出现选择列，表头复选框用于全选或取消选择当前页；标题栏操作变为“删除已选（N）”和“取消”。未选择镜像时删除按钮禁用。

行复选框的值始终是服务端渲染的不可变完整镜像 ID。批量状态只存在于当前 DOM，不写入 URL 或本地存储。用户点击取消、分页链接、提交搜索或清除搜索时自然丢弃选择。

点击“删除已选”先调用批量预检接口。成功后打开原生 `<dialog>`，内容分为：

- “将删除”：未被任何容器引用的镜像，显示首个镜像名称；无 Tag 时显示短 ID 并标注“未标记”。
- “不会删除”：被至少一个现存容器引用的镜像；每张镜像下列出引用容器名称和状态。
- “已不存在”：选择后、预检前已经消失的镜像；若没有则不显示该组。

弹框中的“确定删除”只代表同意删除预检中可删除的候选项，不能绕过执行时的重新检查。请求期间禁用确认按钮，防止重复提交。关闭预检弹框不会清空列表选择。

执行完成后弹框切换为结果状态，展示实际删除、因容器占用跳过、已不存在和删除失败四组以及汇总数量。用户关闭结果弹框或点击“返回列表”时，重新加载带原 `q` 和 `page` 的列表 URL。若服务端返回当前页已超出删除后的总页数，前端使用响应中的建议页码重新加载上一有效页。

## 服务边界与数据模型

在 `ImageInventoryService` 中增加独立的整镜像批量删除能力，不通过 `remove_available_tags()` 组合实现。服务接受规范化后的不可变镜像 ID 元组，并产生明确的预检与执行结果对象。

预检中的每个镜像结果包含：

- 完整镜像 ID、短 ID 和当前 Tags；
- 状态：`deletable`、`in_use` 或 `missing`；
- `in_use` 状态下按名称稳定排序的容器引用详情。

执行结果中的每个镜像结果包含：

- 完整镜像 ID 和可显示名称；
- 状态：`deleted`、`in_use`、`missing` 或 `failed`；
- `in_use` 状态下的最新容器引用详情；
- `failed` 状态下适合展示给本机管理员的 Docker 错误信息。

服务层继续以镜像 ID 为锁粒度。预检不持有跨请求锁；执行时对每张镜像分别加锁，在锁内重新解析镜像、重新读取容器引用，然后调用 `runtime.remove_image(immutable_id)`。这样单项失败或慢操作不会阻止其他镜像得到结果，也不会把预检快照误当作删除授权。

## API

新增两个同源 JSON 接口：

- `POST /api/images/batch-delete-preview`
- `POST /api/images/batch-delete`

预检接口接收 `{ "image_ids": ["sha256:..."] }`。执行接口接收 `{ "image_ids": ["sha256:..."], "query": "当前搜索词", "page": 2 }`，其中 `query` 默认为空字符串，`page` 默认为 1，二者只用于返回列表导航建议。共同的镜像 ID 输入规则为：

- 数组至少 1 项、至多 20 项，与当前分页大小一致；
- 每项必须是非空、以 `sha256:` 开头的完整镜像 ID；
- 不接受重复 ID；
- 除执行接口的 `query` 和 `page` 外，不接受依赖页面状态的删除参数。

预检返回按状态分组的镜像详情。执行接口不要求或接受预检令牌，因为 Docker 状态随时可能改变；它对同一批 ID 重新做权威检查并返回四组逐项结果。前端提交的 ID 只表达用户选择，不表达“未占用”这一信任结论。

输入不合法返回 422。执行接口先读取镜像与容器完成 Docker 可用性预检；该初始读取失败时返回 503，不开始任何删除。进入逐项执行后，单张镜像删除失败记录为 `failed` 并继续处理其余项；因此部分成功仍返回 200 和完整结果，而不是用单个 HTTP 错误覆盖已发生的事实。

两个接口继续受现有同源安全中间件保护。模板内容依赖 Jinja 自动转义，JavaScript 使用 `textContent` 创建名称、容器和错误文本，不拼接不可信 HTML。

## 并发与删除语义

容器占用以 Docker 当前返回的所有现存容器为准，运行中与已停止容器一视同仁。只要容器的不可变 `image_id` 与候选镜像一致，该镜像就整张跳过；不尝试删除它的部分 Tags。

执行按以下顺序处理每个候选项：

1. 通过完整 ID 重新读取镜像；若不存在，记录 `missing`。
2. 读取最新容器列表并按不可变镜像 ID 查找引用；存在引用时记录 `in_use`。
3. 没有引用时调用 Docker 按完整 ID 删除整张镜像。无 Tag 悬空镜像走相同路径。
4. 删除调用报告镜像已不存在时记录 `missing`；其他 Docker 错误记录 `failed`。
5. 继续处理下一个候选镜像。

预检之后新建或保留容器会在第 2 步被发现并安全跳过。Docker 本身不提供“仅在无人引用时删除”的原子比较交换操作，因此检查与删除调用之间仍存在极短外部并发窗口；不使用 `force`，若该窗口内出现引用，Docker 的冲突错误会作为该项 `failed` 返回，不影响其他项。

## 列表刷新与页码

执行接口接收当前 `query` 和 `page` 仅用于计算执行后的导航建议，不参与删除授权。执行结束后服务重新执行相同搜索并计算最新总页数，返回 `suggested_page = min(requested_page, max(total_pages, 1))`。前端使用原查询与建议页码构造同源列表 URL。

若用户在刷新前关闭弹框，页面保留结果；只有明确关闭结果或点击返回列表才导航。预检失败和执行请求整体失败时保留选择及当前页面，显示错误并允许重试。

## 测试策略

### 服务层

- 预检正确区分未占用、运行容器占用、已停止容器占用和已不存在的镜像。
- 被占用项返回全部容器引用并稳定排序。
- 无 Tag 且未占用的悬空镜像通过完整 ID 删除。
- 有 Tag 且未占用的镜像按完整 ID整张删除。
- 预检后新增容器时执行阶段跳过该镜像。
- 某张镜像删除失败后，后续镜像仍继续处理。
- 删除前消失和 Docker 返回 not found 均归入 `missing`。
- 执行结果和建议页码在部分删除后正确计算。

### API

- 校验空数组、超过 20 项、重复 ID、非完整 ID 和错误类型。
- 预检响应包含可删除、占用及容器详情、已不存在分组。
- 执行响应包含已删除、占用跳过、已不存在、失败及建议页码。
- 初始 Docker 枚举失败映射为 503，逐项错误留在 200 响应的失败组。
- 跨源 POST 继续被拒绝。

### Web 与前端

- 列表模板包含批量入口、默认隐藏的选择列、全选框、选择计数和批量弹框。
- 每行复选框使用完整不可变镜像 ID，并保留当前搜索与分页信息。
- 选择状态覆盖单项勾选、全选、部分选择、取消和零选择禁用。
- 预检正确、安全地渲染可删除镜像、悬空镜像和占用容器。
- 执行请求期间禁用按钮，部分结果按组渲染，刷新使用原查询与建议页码。
- 预检或执行整体失败时恢复按钮、保留选择并允许重试。
- 若项目没有 JavaScript 测试框架，将选择与分组所需状态转换抽成无 DOM 副作用的纯函数，并使用仓库已有的轻量运行环境测试；不为本功能引入大型前端依赖。
